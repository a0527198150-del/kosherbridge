# מודול Magisk — גשר כשר (פתרון סופי לנגנים מרוטים)

> **הערה:** האפליקציה עצמה תומכת גם בערוץ **"דרך הרשאת רוט (su)"** — על נגן
> מרוט אפשר לבחור את הערוץ הזה בהגדרות בלי להתקין את המודול (האפליקציה מריצה
> תהליך מורשה בעצמה דרך su). המודול הזה הוא האופציה ה**קבועה** יותר: הוא הופך
> את האפליקציה לאפליקציית מערכת כך שהערוץ הישיר עובד בלי להעניק הרשאת root
> לאפליקציה בכלל.

מודול זה הופך את התקנת האפליקציה על נגן מרוט ל**"מתקינים פעם אחת — עובד לנצח"**:
האפליקציה מותקנת כאפליקציית מערכת (priv-app) עם הרשאת `BLUETOOTH_PRIVILEGED`,
נחסמת חסימת ה-API הנסתר של אנדרואיד, ו**מופעל פרופיל HFP Client**
(`bluetooth.profile.hfp.hf.enabled=true`) — שזה מה שגורם לקול לעבור לנגן.
ברוב הנגנים הסיניים הפרופיל **קיים במחסנית אבל כבוי מהיצרן**, ובלי להדליק אותו
אף ערוץ חיבור לא יספק קול — גם לא Shizuku.

## למה זה הפתרון הסופי

בלי רוט, אנדרואיד חוסם שתי חומות שאי אפשר לעקוף לצמיתות בתוכנה:
1. **API נסתר** — פרופיל הדיבורית (BluetoothHeadsetClient) אינו חלק מה-SDK הציבורי.
2. **הרשאת בלוטוס מיוחסת** (`BLUETOOTH_PRIVILEGED`, `signature|privileged`) —
   ניתנת רק לאפליקציות מערכת.

מודול זה מסיר את שלוש החומות בנגן מרוט:
- האפליקציה מותקנת ב-`/system/priv-app` + אישור ברשימת ההרשאות →
  מקבלת את `BLUETOOTH_PRIVILEGED`.
- `service.sh` מפעיל בהפעלה `settings put global hidden_api_policy 1` →
  ה-reflection אל ה-API הנסתר מותר.
- `system.prop` מגדיר `bluetooth.profile.hfp.hf.enabled=true` → המחסנית
  מפעילה את שירות `HeadsetClientService` בפעם הבאה שהבלוטוס עולה, והנגן חושף
  מכשיר SCO (קול). Magisk מחיל את זה עם resetprop בשלב post-fs-data — **לפני**
  שתהליך הבלוטוס עולה וקורא את ההגדרה, ולכן זה עובד; `setprop` מ-`service.sh`
  היה רץ מאוחר מדי ולא היה משפיע כלל.

> **שינוי אחד בכל גרסה.** המודול מדליק רק את `hfp.hf` ולא פרופילי client אחרים
> (`a2dp.sink`, `avrcp.controller`, `pbap.client`), כדי שאם משהו מתנהג אחרת
> יהיה ברור מה גרם לזה.

האפליקציה עצמה כבר יודעת לעבוד בדרך הישירה — המודול רק נותן לה את ההרשאות.

## מה המודול משנה במכשיר

- מתקין את האפליקציה כאפליקציית מערכת מורשית (priv-app) עם ההרשאה
  `BLUETOOTH_PRIVILEGED` — ההרשאה ניתנת לחבילה הזו בלבד.
- מגדיר `hidden_api_policy=1` בכל אתחול. **שימו לב: זו הגדרה גלובלית למכשיר.**
  היא מרפה את מגבלות ה־API הנסתר של אנדרואיד עבור *כל* האפליקציות בנגן, לא רק
  עבור גשר כשר. במכשיר ייעודי לשימוש הזה זו עסקה סבירה; במכשיר שמשמש גם לדברים
  אחרים כדאי לשקול.
- מגדיר `bluetooth.profile.hfp.hf.enabled=true` באמצעות `system.prop`
  (מוחל בשלב post-fs-data). המאפיין נקרא על ידי תהליך הבלוטוס בעלייה, ולכן
  הוא נכנס לפעולה רק אחרי **אתחול מלא** — התקנה ללא אתחול לא תפעיל את הפרופיל.

## איך בונים

המודול נבנה אוטומטית ב-CI עם כל גרסה (artifact בשם
`kosherbridge-magisk-module`). לבנייה מקומית:

```sh
./gradlew :kosherbridge:assembleDebug
sh magisk-module/build.sh          # נוצר kosherbridge-magisk-v1.zip
```

## איך מתקינים

1. **מרוטים את הנגן** (Magisk מותקן).
2. מעתיקים את קובץ המודול (`kosherbridge-magisk-v1.zip`) לנגן.
3. פותחים את אפליקציית **Magisk** → Modules → **Install from storage** → בוחרים
   את הקובץ.
4. **מאתחלים את הנגן.**
5. פותחים את האפליקציה — עכשיו "פרופיל דיבורית" צריך להראות **"נתמך"**
   באבחון, והחיבור עובד דרך הערוץ הישיר. בוחרים את הטלפון הכשר ומתחברים.

> אם הפרופיל עדיין מראה "לא נתמך" — בדקו באבחון שהאפליקציה מותקנת כמערכת
> (ערוץ פעיל: "ישיר") ואשרו שהמודול פעיל באפליקציית Magisk.

## איך לוודא שהמודול עבד

אחרי התקנת המודול ואתחול, מהמחשב:

```
adb shell getprop bluetooth.profile.hfp.hf.enabled
```

אמור להחזיר `true`. אם הוא חוזר ריק — המודול לא הוחל; ודאו שהוא מופעל
באפליקציית Magisk ושהמכשיר אותחל.

```
adb shell dumpsys bluetooth_manager | grep -i "Profile:"
```

ברשימה אמור להופיע עכשיו **`HeadsetClientService`**. אם הוא מופיע — פרופיל
הדיבורית פעיל, והקול יכול לעבור לנגן.

ואז באפליקציה: הגדרות ← כל הגדרות החיבור ← אבחון. השורה
**"API נסתר (HFP)"** אמורה להראות **"זמין"**.

## איזה ערוץ חיבור לבחור אחרי ההתקנה

כשהמודול מותקן, האפליקציה היא אפליקציית מערכת עם `BLUETOOTH_PRIVILEGED` וה-API
הנסתר פתוח, ולכן:

- **"חיבור ישיר" (DIRECT)** — עובד in-process, בלי תהליכים נוספים ובלי הרשאות
  root לאפליקציה. זה הערוץ הנקי והמומלץ.
- **"רוט (su)"** — ערוץ הגיבוי אם הישיר עדיין נחסם על ידי המחסנית.
- **Shizuku כבר לא נדרש כלל** במכשיר עם המודול הזה.

## מגבלה כנה

גם כמערכת, **ערוץ הקול (SCO) תלוי בשבב הבלוטוס של הנגן**. בנגנים עם
מחסנית בלוטוס תקינה (טלפונים, קופסאות איכותיות) הקול עובד; בשבבים זולים
שאינם תומכים ב-SCO כלל — השליטה עובדת אבל הקול לא, ואין תוכנה שתכריח זאת.
